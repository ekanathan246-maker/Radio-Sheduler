# EMANE TDMA Integration

This directory contains the EMANE configuration used to demonstrate the
TDMA schedule generated by the Python scheduler.

## Integration Overview

The Python TDMA scheduler generates a conflict-free schedule for the
16-node topology.

For the provided 4x4 grid topology:

- Nodes: 16
- Radio range: 500 m
- TDMA slots: 9
- Schedule: conflict-free

The resulting schedule is represented in `tdma-schedule.xml` and published
to the EMANE TDMA Event Scheduler model.

## Schedule

The EMANE schedule uses:

- 1 frame
- 9 slots per frame
- 1000 microsecond slot duration
- 0 microsecond slot overhead
- 1 MHz bandwidth
- 2.4 GHz frequency
- 1 Mbit/s data rate

The node-to-slot mapping follows the schedule generated by the Python
scheduler.

| Slot | Transmitting NEMs |
|------|-------------------|
| 0 | 7 |
| 1 | 10 |
| 2 | 6 |
| 3 | 11 |
| 4 | 3, 15 |
| 5 | 8, 9 |
| 6 | 5, 12 |
| 7 | 2, 14 |
| 8 | 1, 4, 13, 16 |

## EMANE Configuration

`platform-16nem.xml` defines 16 NEMs and connects each NEM to its
corresponding configuration in the `nem/` directory.

Each NEM uses:

- The EMANE virtual transport
- A unique virtual interface (`emane1` through `emane16`)
- A unique address in the `172.30.1.0/24` network
- The TDMA event scheduler radio model

`tdmaradiomodel.xml` contains the TDMA radio-model configuration.

`transvirtual.xml` provides the virtual transport configuration.

## Verification

The EMANE integration was tested using WSL2 and EMANE 1.5.3.

The following was verified:

- EMANE started successfully with 16 NEMs.
- All 16 NEMs accepted the TDMA schedule.
- No schedule rejection was reported.
- NEM 2 reported its assigned transmit slot as slot 7, matching the
  Python scheduler's `Node_02 -> Slot 7` assignment.
- Virtual interfaces `emane1` through `emane16` were created.
- A packet-level connectivity test between EMANE nodes succeeded:
  5 packets transmitted, 5 received, 0% packet loss.

## WSL2 Limitation

The EMANE test was performed under WSL2. The environment reported
real-time thread-priority warnings.

Therefore, this integration demonstrates functional schedule loading,
TDMA configuration, virtual interfaces, and packet-level communication,
but it should not be interpreted as a real-time wireless hardware
validation.

## Files

- `platform-16nem.xml` - 16-NEM EMANE platform configuration
- `tdma-schedule.xml` - TDMA schedule generated from the scheduler result
- `tdmaradiomodel.xml` - TDMA radio model configuration
- `transvirtual.xml` - virtual transport configuration
- `nem/tdmanem-1.xml` through `nem/tdmanem-16.xml` - per-NEM configurations
